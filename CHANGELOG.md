# Changelog

## Unreleased

- Visual regression: a `chromatic` CI job publishes Storybook to Chromatic and snapshots every story in light and dark mode (`npm run chromatic -w @lockin/storybook`). It needs the `CHROMATIC_PROJECT_KEY` secret and is skipped on PRs from forks.
- Hub component pages show a **Live example**: the component's Storybook stories embedded from the static build (`/storybook`), switchable per story and synced with the hub's color mode and theme. New `GET /api/components/:name/stories`. Root `npm run build` now also builds Storybook.
- Specs gain an optional `figma` field (`fileKey`, `nodeId`); all 14 now link their Figma library node (each spec 0.1.0 → 0.2.0). The Live example has **Code** and **Design** tabs; Design is Figma's view-only embed, loaded on first open.
- Hub sidebar lists each component and doc under its section while that section is open.
- Components are organized by atomic design level. Specs gain a required `level` (`atom`, `molecule` or `organism`; all 14 specs 0.2.0 → 0.3.0). Atoms: Button, Icon, Link, Checkbox, Toggle, Tag. Molecules: InputField, Search, Select, RadioGroup, Dropdown, Tabs. Organisms: DataTable, Modal.
- Storybook stories are titled `Atoms/…`, `Molecules/…` and `Organisms/…` (was `Components/…`), filed under `stories/atoms|molecules|organisms/`, and the sidebar lists Foundations, then the three levels. Story ids change accordingly (`atoms-button--primary`).
- Hub: the Components page groups cards by level and component pages show it. `GET /api/components`, the `list_components` tool and search include `level`; the live-example lookup finds stories by level.
- Docs: `components.md` gains an Atomic levels section with a rule of thumb and a table per level; `contributing.md`, `llms.txt` and `AGENTS.md` follow.
- Fonts: `@lockin/tokens` now ships the fonts its family tokens name. Inter (`sans`, `display`) and JetBrains Mono (`mono`) are bundled as variable fonts (Latin and Latin Extended, SIL OFL 1.1, licenses included) in `dist/fonts/`, exported as `@lockin/tokens/fonts/*`, and their `@font-face` rules are inlined into `tokens.css` and every theme sheet, so existing imports pick them up. The hub serves them at `/assets/fonts/`. Before this, every render used the system fallback fonts. React Native still uses the system font.
- Specs: removed em dashes and numeric en dashes from spec text ("— use Link" is now "; use Link", "1–3 words" is now "1 to 3 words"); 13 specs 0.3.0 → 0.3.1. The Figma library docs follow: Docs frames show the spec version and atomic level, and Getting Started, Cover and Changelog were corrected (variable count, Icon only and Select variant counts, WCAG 2.1, no `submit_feedback` tool, no CI claim).
- Docs: new `token-naming.md` explains the token naming scheme (one path as the name everywhere, the three layers, semantic groups and leaf names, scale vocabularies, mode and theme handling, the `ds` prefix) with a checklist for naming a new token and a list of open questions. `tokens.md` now lists the intent token parts correctly (only `secondary` has `border`; `disabled` has `bg` and `text`).
- BREAKING, CSS variables: camelCase token parts are now kebab-case in CSS custom properties (`--ds-color-text-linkHover` is `--ds-color-text-link-hover`). Affected parts: `bgHover`, `bgActive`, `onBrand`, `onSolid`, `linkHover`, `ringOffset`, `touchTarget`, `lineHeight`, `letterSpacing`, `underlineOffset`, `lineThrough`, `zIndex` (37 variables). Token names are unchanged in JS, React Native, JSON, REST and MCP; the flat JSON `cssVar` field has the new names. The build fails if two paths would map to one variable. Component and hub CSS were updated, `Icon` converts its `color` prop, and the Figma variables' web code syntax was updated to match (28 variables).
- Storybook: every story now runs as a test in headless Chromium with axe (WCAG 2.1 AA), via `@storybook/addon-vitest`. `npm test -w @lockin/storybook` runs them; root `npm run build` and `npm test` include them. Needs `npx playwright install chromium` once per machine. Added `@storybook/addon-mcp`, which serves the stories and runs tests for agents at `http://127.0.0.1:6006/mcp` while Storybook is running.
- Fixed: RadioGroup no longer puts `aria-required` on its `<fieldset>` (not allowed by ARIA); `required` is now set on each radio input (spec 0.3.1 → 0.3.2). Search `Sizes` story names its landmarks, and the disabled color swatches in the Foundations stories are marked `aria-disabled` so axe skips them.
- Docs: new Agent tooling diagram in `architecture.md` (`agent-mcp-servers`) showing the lockin and Storybook MCP servers and the shared story tests.

## 0.1.0 — 2026-10-13

Initial scaffold: tokens (base + semantic, light/dark, 2 project themes), 14 components for web and React Native, AI-readable specs, docs, and the hub server (REST, MCP, web UI, auth, versioning, feedback).
