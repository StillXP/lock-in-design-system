# Figma token sync

> How the design tokens map to Figma Variables, and how to produce the payload that updates them.

Code is the source of truth. Sync runs one way, from code to Figma. Nothing in Figma writes back to `packages/tokens/src/`.

The Figma library is https://www.figma.com/design/1dgB7LeRgTrVIenTmmrlvr. It was first built by hand from the tokens; this page writes down the rules that build followed, so it can be repeated.

## Generating the payload

```
npm run figma -w @lockin/tokens
```

This reads `packages/tokens/src/` and writes `packages/tokens/dist/figma/variables.json`. It does not touch Figma. Applying the payload (creating, updating and flagging variables through the Figma plugin API) is a separate step.

The payload has two keys:

- `collections`: each with a `name`, `modes`, and `variables`.
- `skipped`: tokens that are not variables, grouped by token type.

Each variable has a `name`, a Figma `type` (`COLOR`, `FLOAT` or `STRING`), a `values` object keyed by mode name, an optional `description`, and `codeSyntax`. A value is either a literal or `{ "alias": "<Collection>/<variable name>" }`. Colors are `{ r, g, b, a }` with channels from 0 to 1.

## Collections

| Collection | Source tokens | Modes | Notes |
| --- | --- | --- | --- |
| Primitives | Base palette (`color.<hue>.<step>`) and `color.brand.*` | `Value` | Hidden from publishing, no scopes. `brand/N` aliases `blue/N`. |
| Color | Semantic colors (`color.background`, `surface`, `text`, `icon`, `border`, `focus`, `intent`, `status`, `dataviz`) | Light, Dark, plus Light and Dark for each theme | Aliases Primitives, or other Color variables. |
| Dimensions | `space`, `size`, `radius`, `border`, `focus`, `breakpoint` | `Value` | `FLOAT`, in px. |
| Typography | `font.family`, `font.size`, `font.weight`, `font.lineHeight`, `font.letterSpacing` | `Value` | See the unit rules below. |

## Naming

- Drop the `color.` prefix for color variables, then replace dots with slashes: `color.text.primary` becomes `text/primary`, `color.blue.600` becomes `blue/600`.
- Other tokens keep their full path: `space.md` becomes `space/md`, `font.size.lg` becomes `font/size/lg`.
- Alias targets include the collection: `Primitives/blue/700`, `Color/text/primary`.
- Every variable gets WEB code syntax `var(--ds-...)`, the same custom property the CSS build emits.

## Color modes and themes

Each theme in `packages/tokens/src/themes/` becomes a pair of modes named `<Theme> Light` and `<Theme> Dark`. A new theme file adds its modes the next time the payload is generated.

To build a themed mode:

1. Load the tokens with the theme applied and read the light or dark value.
2. In the default Light and Dark modes, a reference to `color.brand.N` stays an alias to `Primitives/brand/N`. In a themed mode it becomes an alias to `Primitives/<hue>/N`, where the hue is the theme's brand. Themes never remap `Primitives/brand/N` itself, because Primitives has only one mode.
3. A reference to another semantic color becomes an alias to that Color variable.
4. Tokens with `ds.alpha` (the modal scrim) have the alpha baked in, so they are literal RGBA values, not aliases.
5. `transparent` becomes RGBA `0, 0, 0, 0`.

## Units and types

- Dimensions are plain numbers in px. The CSS build converts some to rem; Figma keeps px.
- `font.letterSpacing` is `em` in code and a percent in Figma, so `-0.02em` becomes `-2`.
- `font.family` is a `STRING` holding only the first family (`Inter`). Figma can't hold a fallback stack. The full stack stays in code.
- `font.lineHeight` is a multiplier in code and a percent in Figma, so `1.2` becomes `120`.
- `font.weight` is a unitless number.
- A token that references another token in the same collection stays an alias.

## Not variables

These are in `skipped` and are not synced as variables:

- `shadow.*`: Figma effect styles (`shadow/sm` to `shadow/xl`).
- `typography.*`: Figma text styles, bound to the Typography variables.
- `motion.*`, `zIndex.*`, `font.decoration.*`, `font.transform.*`, `font.underlineOffset.*`: no Figma equivalent that components use.

Text and effect styles are not generated by this script yet. They still have to be kept in step with `typography.*` and `shadow.*` by hand.

## After the payload is applied

Publishing the library has to be done in Figma by hand; the plugin API can't do it. The same goes for anything that depends on mode switching in prototypes.

When tokens change, regenerate the payload, apply it, then publish.
